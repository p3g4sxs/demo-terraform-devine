Despliega un portal web en AWS con Terraform

En este workshop vas a crear desde cero un bucket S3 con un sitio web estático servido a través de CloudFront. Al finalizar tendrás tu propio portal funcionando en producción.

⏱️~45 min duración
📊Nivel: principiante
☁️Cloud: AWS
🛠️Stack: S3 + CloudFront + Terraform
★
Objetivo del workshop
Qué vas a construir hoy

Al ejecutar terraform apply se van a crear automáticamente los siguientes recursos en tu cuenta AWS:

aws_s3_bucket aws_s3_bucket_versioning aws_s3_bucket_server_side_encryption_configuration aws_s3_bucket_public_access_block aws_s3_bucket_policy aws_cloudfront_origin_access_control aws_cloudfront_distribution aws_s3_object (archivos del portal)
💡

Dato clave: Todo esto se hace con 3 comandos: terraform init, terraform plan y terraform apply. Terraform detecta las dependencias entre recursos y los crea en el orden correcto automáticamente.

2
Configurar credenciales AWS
Las llaves de acceso te las proporciona el instructor
⏰

Importante: Las credenciales de este workshop son temporales y solo funcionan el día de hoy de 10:00 AM a 12:00 PM (hora Colombia). Después de ese horario quedarán inactivas automáticamente.

a

Crear o editar el archivo de credenciales

Abre (o crea) el archivo ~/.aws/credentials y agrega este bloque:

ini — ~/.aws/credentials 
[terraform-workshop]
aws_access_key_id     = TU_ACCESS_KEY_AQUI
aws_secret_access_key = TU_SECRET_KEY_AQUI
💡

En macOS/Linux el archivo está en ~/.aws/credentials. En Windows en C:\Users\TU_USUARIO\.aws\credentials. Si la carpeta .aws no existe, créala.

b

Verificar que las credenciales funcionan

bash 
aws sts get-caller-identity --profile terraform-workshop
✓ Salida esperada
{
  "UserId": "AIDAXXXXXXXXXXXXXXXXX",
  "Account": "XXXXXXXXXXXX",
  "Arn": "arn:aws:iam::XXXX:user/terraform-capacitacion-demo"
}
🚨

Si ves InvalidClientTokenId o AccessDenied, verifica que copiaste bien la key y el secret. Si el error persiste, avísale al instructor.

4
Ajustar terraform.tfvars
El nombre del bucket S3 debe ser único globalmente en AWS
⚠️

Importante: Los nombres de buckets S3 son únicos a nivel global en toda AWS. Si otro participante usa el mismo nombre, el deploy fallará. Usa tu nombre o iniciales como sufijo.

a

Abre el archivo terraform.tfvars

bash 
code terraform.tfvars       # VS Code
# o
nano terraform.tfvars      # terminal
b

Cambia el valor de portal_bucket_name

hcl — terraform.tfvars 
aws_region   = "us-east-1"
project_name = "terraform-capacitacion"
environment  = "demo"

# ✏️ Cambia "tu-nombre" por tus iniciales o nombre
portal_bucket_name = "terraform-capacitacion-portal-tu-nombre"

force_destroy_bucket   = true
cloudfront_price_class = "PriceClass_100"
cloudfront_comment     = "Portal de Capacitación Terraform"
✅

Ejemplos válidos: terraform-capacitacion-portal-juan, terraform-capacitacion-portal-jgomez, terraform-capacitacion-portal-2oct

5
terraform init
Descarga el provider de AWS — siempre es el primer paso

terraform init descarga el provider de AWS que está definido en providers.tf. Es equivalente a un npm install — solo necesitas correrlo una vez al clonar el repo.

bash 
terraform init
✓ Salida esperada
Initializing the backend...
Initializing provider plugins...
- Finding hashicorp/aws versions matching "~> 5.0"...
- Installing hashicorp/aws v5.x.x...
- Installed hashicorp/aws v5.x.x (signed by HashiCorp)

Terraform has been successfully initialized!
📁

Después del init se crea la carpeta .terraform/ con el binario del provider. No la subas al repo — ya está en el .gitignore.

6
terraform plan
Previsualiza los cambios — no hace nada en AWS

terraform plan compara tu código con el estado actual de AWS y muestra exactamente qué va a crear, modificar o destruir. No hace ningún cambio real.

bash 
terraform plan
✓ Salida esperada (resumen final)
  + resource "aws_s3_bucket" "portal" { ... }
  + resource "aws_cloudfront_distribution" "portal" { ... }
  + resource "aws_s3_object" "web_files" { ... }
  ...

Plan: 8 to add, 0 to change, 0 to destroy.
💡

Los símbolos del plan: + crear   ~ modificar   - destruir. Si ves destrucciones inesperadas, detente y revisa antes de continuar.

7
terraform apply
Crea la infraestructura real en AWS (~3 minutos)
⚠️

Este comando crea recursos reales en AWS. Revisa el plan del paso anterior antes de confirmar. Cuando Terraform pregunte Enter a value: escribe yes y presiona Enter.

bash 
terraform apply
✓ Terraform preguntará confirmación
Do you want to perform these actions?
  Terraform will perform the actions described above.
  Only 'yes' will be accepted to approve.

  Enter a value: yes
✓ Salida al finalizar (~3 minutos)
Apply complete! Resources: 8 added, 0 changed, 0 destroyed.

Outputs:

portal_url = "https://xxxxxxxxxx.cloudfront.net"
🎉

¡Listo! El output portal_url es la URL de tu portal. Ábrela en el navegador — puede tardar 1-2 minutos en propagarse por la red de CloudFront.

8

bash

9
Explorar el state
Observa cómo Terraform registra lo que creó

El state (terraform.tfstate) es la memoria de Terraform: sabe exactamente qué recursos creó, con qué IDs y en qué estado están.

a

Listar todos los recursos gestionados

bash 
terraform state list
✓ Salida esperada
aws_cloudfront_distribution.portal
aws_cloudfront_origin_access_control.portal
aws_s3_bucket.portal
aws_s3_bucket_policy.portal
aws_s3_bucket_public_access_block.portal
aws_s3_bucket_server_side_encryption_configuration.portal
aws_s3_bucket_versioning.portal
aws_s3_object.web_files["index.html"]
b

Ver detalles del bucket S3

bash 
terraform state show aws_s3_bucket.portal
10
terraform destroy
Elimina todos los recursos y evita costos en AWS
🗑️

Este comando elimina permanentemente todos los recursos creados en AWS. Solo ejecútalo cuando hayas terminado el workshop. Los recursos de CloudFront generan costos si se dejan activos.

bash 
terraform destroy
✓ Salida al finalizar
Destroy complete! Resources: 8 destroyed.
🏆
